# i18n Rule

## Source of truth

- ADR: `docs/decisions/0005-i18n-paraglide.md`
- ADR: `docs/decisions/0007-i18n-facade-and-key-shape.md` (facade + key shape)

## DO

- **DO** add every user-facing string to `messages/<locale>.json` and import the message function from `$core/i18n` (the facade re-exports Paraglide's compiled output along with `locales` and `localeCookieName`).
- **DO** key messages with the snake_case + group-prefix convention from ADR 0007 (`auth_login_title`, `camera_list_empty`). Keys are stable; values change.
- **DO** ship `messages/en.json` only on day one. Adding `id`, `ja`, etc. is dropping a JSON file plus translation, no refactor.
- **DO** resolve the locale server-side. The current locale comes from a `locale` cookie, defaults to `en`.
- **DO** wrap user-facing strings with named ICU placeholders for variables: `"Welcome, {name}"`. Never concatenate.
- **DO** include strings in errors and toasts. Error UX is part of i18n.

## DON'T

- **DON'T** hardcode user-facing English (or any other language) in components, route loaders, or services.
- **DON'T** ship raw error messages from the backend to the user without a localized wrapper. The backend speaks contract, not UX.
- **DON'T** put markup inside a message string. If you need bold, use a snippet/component and pass the raw text in.
- **DON'T** translate keys. Keys stay English.
- **DON'T** lazy-load the catalog at runtime. Paraglide compiles per-locale modules; tree-shake handles unused messages.

## Pattern

```ts
// messages/en.json
{
  "auth_login_title": "Sign in to your account",
  "auth_login_submit": "Sign in",
  "camera_list_empty": "No cameras yet. {action}",
  "common_error_generic": "Something went wrong. Please try again."
}
```

```svelte
<script lang="ts">
  import { m } from '$core/i18n'
</script>

<h1>{m.auth_login_title()}</h1>
<button>{m.auth_login_submit()}</button>
```

## Lint

A repo-local lint rule (or a code-review checklist item) catches string literals in user-facing positions:

- text children of HTML elements in `*.svelte` files
- `toast.success(...)` / `toast.error(...)` first argument
- `throw new Error(...)` strings that surface to UI

Keys may slip — the lint catches the strings, not the keys.

## Locale switching

```ts
// $core/i18n/setLocale.ts (server-only action target)
export async function setLocale(locale: 'en' | 'id', cookies: Cookies) {
  cookies.set('locale', locale, { path: '/', sameSite: 'lax', maxAge: 60 * 60 * 24 * 365 })
}
```

A locale switch sets the cookie and reloads. No client-side magic.

## Quick reference

| Want to… | Do this |
|---|---|
| Add a string | Add a key+value to `messages/en.json`, import via `$core/i18n` |
| Add a locale | Drop `messages/<locale>.json`, translate, run `bun run codegen` |
| Show a server error | Map error codes to localized i18n keys using the `api_error_*` snake_case convention (the lookup table will live in `core/api` per ADR 0007 follow-ups) |
| Use a variable | ICU placeholders: `"Hello, {name}"` |
